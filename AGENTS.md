# AGENTS.md

## What this repo is

Personal LLM study notes (Chinese). The site is built with VitePress and is meant to publish notes written directly as Markdown or Jupyter notebooks. No application code, no tests.

## Commands

- `uv run jupyter lab` — run notebooks (Python 3.14, managed by uv)
- `npm install` — install VitePress and Markdown/notebook rendering dependencies
- `npm run content:sync` — scan note folders, create missing notebook wrapper pages, and regenerate sidebar/notebook manifests
- `npm run dev` — run `content:sync`, then start the VitePress dev server
- `npm run build` — run `content:sync`, then build the site (output: `.vitepress/dist/`)
- `npm run preview` — preview built docs locally

## Content Workflow

Write notes directly in topic folders such as `basis/`, `math/`, `optimizer/`, and `roadmap/`. Any non-hidden top-level folder that contains `.md` or `.ipynb` files is treated as content. Markdown files are rendered as normal VitePress pages. Jupyter notebooks are detected automatically; `scripts/sync-content.mjs` creates a small generated `.md` wrapper under the current folder's `_notebooks/` subfolder, then the Vue `NotebookViewer` component renders notebook markdown, code cells, outputs, images, and KaTeX math in the browser.

Do not manually edit `.vitepress/sidebar.generated.ts` or `.vitepress/notebooks.generated.ts`; both are rebuilt by `npm run content:sync`. Do not edit generated notebook wrapper pages unless changing the generator. They start with:

```md
<!-- Generated by scripts/sync-content.mjs. Edit the source .ipynb instead. -->
```

If a notebook and a hand-written Markdown note would use the same slug, the sync script preserves the hand-written `.md` and creates a `*-notebook.md` page instead.

When a notebook is moved or deleted, `npm run content:sync` removes stale generated wrapper pages that still carry the generated marker. It never deletes normal hand-written Markdown notes.

## Site Architecture

`.vitepress/config.ts` imports the generated sidebar and keeps VitePress configuration minimal. `.vitepress/theme/NotebookViewer.vue` reads `.vitepress/notebooks.generated.ts` to load notebook files. `.vitepress/theme/HomeLanding.vue` and `.vitepress/theme/style.css` define the custom visual style. New content normally does not require manual config edits.

## Gotchas

- No linter, formatter, typecheck, or test runner. There is nothing to run for verification.
- `README.md` and `AGENTS.md` are excluded from VitePress via `srcExclude` in `.vitepress/config.ts` — they won't appear on the site.
- `package-lock.json` is committed but `node_modules/` is gitignored. Run `npm install` before docs work.
- Python deps managed by `uv` (see `uv.lock`). No pip/requirements.txt.
- CI uses `npm ci` (not `npm install`), node 22. Deploys to GitHub Pages on push to `main`.
- VitePress base path is `/llm-lab/`. Markdown uses MathJax3; notebook rendering uses KaTeX. Language is `zh-CN`.
